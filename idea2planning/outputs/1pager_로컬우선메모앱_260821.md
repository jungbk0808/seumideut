# [26.08.21] 로컬 우선 메모 앱 MVP 및 멀티 플랫폼 확장 제안 (개인 프로젝트)

## 1. 프로젝트 한 줄 요약

본 프로젝트는 사용자가 인터넷 연결이나 계정 생성 없이도 빠르고 안정적으로 메모를 작성·관리할 수 있는 **로컬 우선 데스크톱 메모 앱 MVP**를 만들고, 이후 데스크톱·웹·모바일 간 동기화가 가능한 크로스 플랫폼 메모 서비스로 확장하는 프로젝트입니다.

## 2. 대상

| 대상 | 상황/특징 |
|---|---|
| 개인 사용자 | 생각, 할 일, 코드 조각, 글감 등을 빠르게 기록하고 싶은 사용자 |
| 지식 작업자 | 여러 메모 앱을 써봤지만 느린 실행, 복잡한 구조, 동기화 불안정에 피로를 느끼는 사용자 |
| 개발자/크리에이터 | 로컬 파일 기반의 빠른 기록과 향후 멀티 디바이스 접근을 모두 원하는 사용자 |
| 초기 MVP 사용자 | 우선 한 대의 컴퓨터에서만 안정적으로 작동해도 충분한 사용자 |

## 3. 문제 정의

### 고객 문제

- 기존 메모 앱은 계정 생성, 클라우드 연동, 복잡한 기능 때문에 "바로 적기"까지의 진입 시간이 길 수 있음
- 단순 메모와 장기 지식 관리 사이에서 적절한 균형을 제공하는 앱을 찾기 어려움
- 동기화 기능이 있는 앱은 편리하지만, 초기 사용 시 로컬 데이터 통제감이 낮게 느껴질 수 있음
- 데스크톱에서 빠르게 쓰기 시작하고 나중에 모바일·웹으로 확장하고 싶은 니즈가 있음

### 비즈니스 문제

- 메모 앱 시장은 경쟁이 치열해 범용 기능만으로는 차별화가 어려움
- 처음부터 웹·모바일·동기화까지 모두 만들면 MVP 출시 속도가 늦어질 위험이 큼
- 동기화, 계정, 결제, 보안, 충돌 처리까지 한 번에 구현하면 개발 복잡도가 급격히 증가함
- 초기 사용자의 실제 메모 습관을 검증하기 전에 과도한 플랫폼 확장이 발생할 수 있음

### 데이터 기반 현황

| 항목 | 현재 수치/상태 | 인사이트 |
|---|---:|---|
| MVP 지원 플랫폼 | 데스크톱 로컬 앱 1개 | 초기 범위를 좁혀 빠르게 사용성 검증 가능 |
| 동기화 지원 | 미지원 | 초기에는 복잡도를 줄이고, 데이터 모델을 확장 가능하게 설계해야 함 |
| 계정 시스템 | 미지원 | 온보딩 마찰을 최소화할 수 있음 |
| 핵심 사용 흐름 | 메모 작성·조회·수정·삭제 | 메모 앱의 기본 가치를 먼저 검증해야 함 |
| 향후 목표 플랫폼 | 데스크톱, 웹, 모바일 | 초기 구조 설계 시 데이터 저장·동기화 확장성을 고려해야 함 |

### Root Cause

#### Case 1.

많은 메모 앱이 초기부터 협업, 클라우드, 템플릿, AI 등 기능을 많이 제공하면서 "빠르게 적는 경험"이 무거워짐

#### Case 2.

로컬 우선 사용성과 멀티 디바이스 동기화는 모두 중요하지만, 두 요구를 동시에 완성하려 하면 MVP 범위가 과도하게 커짐

#### Case 3.

메모 앱의 핵심 가치는 사용자의 반복 사용 습관에서 나오는데, 초기에는 기능 수보다 실행 속도·작성 흐름·검색 경험이 더 중요함

## 4. 목표

| 항목 | 목표 수치 |
|---|---:|
| 앱 실행 후 새 메모 작성 시작 시간 | 2초 이내 |
| 기본 CRUD 기능 완성도 | MVP 기준 100% |
| 로컬 저장 안정성 | 저장 실패율 0% 목표 |
| 초기 사용성 검증 | 5~10명 파일럿 사용자 피드백 확보 |
| MVP 범위 | 계정/동기화 없이 로컬 데스크톱 앱 출시 |
| 확장 준비 | 추후 동기화를 고려한 메모 데이터 모델 설계 |

## 5. 현황 및 분석

### 예상 사용자 Voice

- "메모 앱은 많은데, 막상 바로 쓰려면 무겁거나 복잡하다"
- "처음부터 가입하거나 클라우드 연결하는 앱은 부담스럽다"
- "일단 내 컴퓨터에 안전하게 저장되고, 나중에 폰에서도 보면 좋겠다"
- "검색과 정리가 쉬우면 계속 쓸 것 같다"

### 시장/제품 흐름

- Notion, Obsidian, Apple Notes, Google Keep 등 다양한 메모/노트 앱이 이미 존재함
- 기존 강자는 각각 장점이 뚜렷함: 협업, 로컬 파일, 모바일 접근성, 생태계 연동
- 신규 앱은 "모든 기능"보다 특정 사용 맥락에서 더 빠르고 단순한 경험을 제공해야 진입 여지가 있음
- 로컬 우선 구조는 신뢰감과 속도 측면에서 강점이 있으나, 장기적으로는 동기화 기대를 충족해야 함

## 6. 해결방안

### Phase 1. 로컬 데스크톱 MVP

#### 제공 기능

- 메모 생성, 조회, 수정, 삭제
- 메모 목록과 상세 편집 화면
- 제목/본문 기반 검색
- 로컬 저장소 기반 데이터 보관
- 기본 정렬: 최근 수정순
- 자동 저장
- 빈 상태, 저장 실패, 삭제 확인 등 기본 상태 처리

#### 예상 효과

- 복잡한 백엔드 없이 빠르게 MVP 출시 가능
- 사용자가 "빠르게 적고 다시 찾는 경험"을 검증 가능
- 향후 동기화 구조를 위한 핵심 데이터 모델 검증 가능

### Phase 2. 데스크톱 앱 고도화

#### 제공 기능

- 태그 또는 폴더
- 즐겨찾기/고정 메모
- 단축키 기반 빠른 작성
- 마크다운 지원 여부 검토
- 백업/내보내기 기능
- 로컬 데이터 마이그레이션 구조

#### 예상 효과

- 반복 사용성을 높이고 개인 지식 관리 도구로 확장
- 동기화 전 단계에서 데이터 안정성 확보

### Phase 3. 웹·모바일·동기화 확장

#### 제공 기능

- 계정 시스템
- 클라우드 동기화
- 멀티 디바이스 메모 조회/수정
- 충돌 처리 정책
- 오프라인 작성 후 온라인 복구 시 동기화
- 선택적 암호화 또는 보안 옵션

#### 예상 효과

- 로컬 앱에서 시작한 사용자가 여러 환경에서 계속 사용할 수 있음
- 장기적으로 유료 기능, 백업, 협업, AI 요약 등 확장 가능

## 7. 리스크

| 영향도 | 리스크 | 대응 방안 |
|---|---|---|
| High | 기존 메모 앱과 차별점 부족 | MVP 단계에서 "빠른 로컬 작성 경험"에 집중하고 핵심 사용성을 뾰족하게 정의 |
| High | 나중에 동기화 추가 시 데이터 구조 변경 비용 증가 | 초기부터 메모 ID, 수정 시각, 삭제 상태, 버전 필드 등 확장 가능한 데이터 모델 설계 |
| Medium | 로컬 저장 데이터 손상 또는 유실 | 자동 저장, 백업 파일, 저장 실패 알림, 내보내기 기능 준비 |
| Medium | MVP 범위가 커져 출시가 지연됨 | Phase 1에서는 계정, 클라우드, 모바일, 협업, AI 기능 제외 |
| Low | 사용자가 로컬 전용 앱에 장기 가치를 느끼지 못함 | 향후 확장 로드맵을 명확히 하고, 백업/내보내기로 신뢰 확보 |

## 8. 중요도 및 긴급도

### 중요도: 상

- 메모 앱의 핵심 가치는 사용자가 매일 반복해서 쓰는 기본 경험에 있음
- 초기에 로컬 MVP를 통해 작성 속도, 저장 안정성, 검색 편의성을 검증하면 이후 플랫폼 확장의 기준을 세울 수 있음
- 동기화 기능보다 먼저 데이터 모델과 사용 흐름을 안정화하는 것이 장기 확장성에 중요함

### 긴급도: 중

- 반드시 특정 날짜까지 출시해야 하는 외부 일정은 아직 없음
- 다만 기능 욕심이 커지기 쉬운 제품군이므로, 빠르게 MVP 범위를 확정하고 실제 사용 가능한 버전을 만드는 것이 중요함
