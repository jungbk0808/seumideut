## 0. 문서 개요

### 0-1. 프로젝트 요약

로컬 컴퓨터에서만 동작하는 가벼운 데스크톱 메모 앱 MVP를 만든다. 사용자는 계정 생성, 클라우드 동기화, 복잡한 문서 기능 없이 앱을 실행하자마자 메모를 작성하고 저장할 수 있어야 한다.

MVP의 핵심 가치는 다음과 같다.

- 빠른 실행과 빠른 작성
- 로컬 저장 기반의 단순하고 안정적인 사용
- 데스크톱 환경에 최적화된 접근성
- 글자수 확인이 필요한 메모/글쓰기 상황 지원
- 마크다운 형식의 가벼운 작성과 읽기 지원
- 향후 웹, 모바일, 동기화 확장을 고려한 데이터 구조 확보

### 0-2. 배경

#### 현재 상황

사용자는 다양한 메모 앱을 선택할 수 있지만, 많은 앱이 계정, 동기화, 협업, 템플릿, AI, 데이터베이스형 구조 등으로 무거워져 있다. 이번 프로젝트는 우선 개발자 본인이 실제로 매일 쓸 수 있는 최소 기능 앱을 1~2주 내에 만드는 것을 목표로 한다.

#### 문제 정의

| 문제 | 설명 |
|---|---|
| 빠른 메모 진입 어려움 | 기존 앱은 실행, 로딩, 화면 전환, 계정 연동 등으로 즉시 작성 경험이 약할 수 있음 |
| 데스크톱 접근성 부족 | 상단 고정, 위젯형 표시 등 데스크톱 작업 흐름에 붙는 기능이 부족함 |
| 기능 과잉 | 올인원 앱은 강력하지만 단순 메모 목적에는 부담이 큼 |
| 글자수 확인 불편 | 짧은 글, 제출용 텍스트, SNS 문안 작성 시 별도 글자수 계산 도구가 필요함 |

#### 사용자 Voice

> "복잡한 앱 말고 그냥 바로 적고 싶다."

> "작업하면서 한쪽에 띄워두는 작은 메모장이 필요하다."

> "글자수 제한 있는 문장을 쓸 때 공백 포함/제외를 바로 보고 싶다."

## 1. 목표

### 1-1. 프로젝트 목표

#### 사용자 목표

- 앱 실행 후 2초 이내 새 메모 작성 가능
- 메모 작성 중 자동 저장으로 저장 부담 제거
- 작성 중 공백 포함/공백 제외 글자수를 실시간 확인
- 데스크톱에서 항상 접근 가능한 메모 경험 제공

#### 제품 목표

- 1~2주 내 실제 사용 가능한 로컬 데스크톱 MVP 완성
- 이후 동기화 확장에 대비한 데이터 모델 설계
- 기능을 최소화하되 매일 쓸 수 있는 품질 확보

#### 운영 목표

- 개인 프로젝트 기준으로 개발, 디자인, QA를 단순하게 운영
- 본인 사용 기반으로 빠르게 피드백 수집
- 가능하면 1~3명 지인 파일럿 테스트 진행

### 1-2. 성공 기준

| 지표 | 현재 | 목표 |
|---|---:|---:|
| MVP 출시 여부 | 없음 | 1~2주 내 사용 가능 버전 |
| 앱 실행 후 작성 가능 시간 | 미정 | 2초 이내 |
| 메모 CRUD 완성도 | 없음 | 100% |
| 자동 저장 | 없음 | 입력 후 자동 저장 |
| 글자수 표시 | 없음 | 공백 포함/제외 실시간 표시 |
| 로컬 저장 실패율 | 미정 | 일반 사용 중 0% 목표 |
| 본인 실사용 | 없음 | 최소 7일 연속 사용 |

정성 목표:

- "내가 실제로 계속 켜두고 쓰고 싶다"는 수준의 가벼움 확보
- 저장/삭제/재실행 상황에서 불안하지 않은 사용감 제공
- 기능이 적어도 핵심 흐름이 막히지 않는 상태 달성

## 4. 정책 정의

### 4-1. 기본 정책

| 항목 | 정책 |
|---|---|
| 사용 방식 | 로컬 데스크톱 앱 |
| 계정 | 미지원 |
| 네트워크 | 필수 아님 |
| 저장 위치 | 기본 앱 데이터 디렉터리의 로컬 저장소 |
| 저장 경로 변경 | MVP 이후 설정 화면에서 사용자 지정 저장 경로를 지원하는 것을 검토 |
| 동기화 | MVP 제외 |
| 기본 정렬 | 최근 수정순 |
| 자동 저장 | 입력 후 자동 저장 |
| 삭제 | 삭제 확인 후 수행 |
| 글자수 계산 | 공백 포함/공백 제외 모두 표시 |
| 본문 형식 | 마크다운 원문 텍스트로 저장 |
| 마크다운 보기 | 위젯은 렌더링 보기만 제공하고, 전체 메모 화면은 마크다운 코드 보기를 제공 |
| 창 구성 | 위젯의 `+`는 현재 위젯 옆에 빈 메모 위젯을 새로 열며, 위젯 창은 여러 개 열 수 있다. 전체 메모 창은 하나만 열고 다시 열 때 기존 창을 앞으로 가져온다. 전체 메모의 `위젯으로`는 선택한 메모의 위젯이 이미 열려 있으면 그 창을 앞으로 가져오고, 다른 메모의 위젯만 열려 있으면 그 옆에 새 창을 연다 |
| 전체 메모 창 제어 | 전체 메모 화면 상단에 최소화, 최대화/복원, 닫기 버튼을 제공한다. 새 메모 액션은 `새 메모` 글자 버튼으로 표시하고, 현재 전체 메모 창의 목록과 편집 영역에서 새 메모를 작성한다 |
| 지원 플랫폼 | MVP는 데스크톱 1개 플랫폼 우선 |

### 4-2. 상태값 정의

| 상태 | 설명 |
|---|---|
| EMPTY | 메모가 없거나 선택된 메모가 없는 상태 |
| DRAFT | 새 메모가 생성되었지만 내용이 비어 있거나 작성 중인 상태 |
| SAVING | 자동 저장 중인 상태 |
| SAVED | 마지막 변경 사항이 저장된 상태 |
| SAVE_FAILED | 저장 실패 상태 |
| DELETED | 사용자가 삭제한 상태 |
| PINNED | 상단 고정 또는 고정 표시된 상태 |
| WIDGET | 위젯형 창으로 표시 중인 상태 |
| MARKDOWN_PREVIEW | 마크다운이 적용된 렌더링 보기 상태 |
| MARKDOWN_SOURCE | 마크다운 원문 코드 보기 상태 |

### 4-3. 예외 정책

| 상황 | 처리 |
|---|---|
| 로컬 저장 실패 | 사용자에게 저장 실패 상태를 표시하고 재시도 제공 |
| 파일/DB 손상 | 백업 파일 또는 마지막 정상 상태 복구 시도 |
| 앱 강제 종료 | 마지막 자동 저장 시점 기준으로 복구 |
| 빠른 연속 입력 | 입력마다 즉시 저장하지 않고 짧은 debounce 후 저장 |
| 메모 삭제 실수 | 삭제 전 확인 모달 표시 |
| 빈 메모 생성 | 제목/본문이 모두 비어 있으면 목록에 노출하지 않거나 자동 정리 |
| 매우 긴 메모 입력 | 최소 10,000자까지 입력 및 글자수 계산 지원 |
| 줄바꿈 포함 글자수 계산 | 공백 포함 기준에는 줄바꿈 포함, 공백 제외 기준에는 스페이스/탭/줄바꿈 제외 |
| 위젯 창 닫기 | 앱 종료가 아니라 위젯 닫힘으로 처리, 메인 앱 데이터는 유지 |
| 앱 업데이트 후 데이터 구조 변경 | 버전 필드를 기준으로 마이그레이션 수행 |

## 5. 서비스 구조

### 5-1. 서비스 흐름

```text
앱 실행
 → 로컬 데이터 로드
 → 메모 목록 표시
 → 메모 선택 또는 새 메모 생성
 → 마크다운 본문 작성
 → 마크다운 렌더링 보기 또는 코드 보기 확인
 → 자동 저장
 → 글자수 실시간 표시
 → 검색/고정/삭제 등 보조 행동
 → 앱 종료 후 재실행 시 기존 메모 복구
```

### 5-2. 유저 플로우

1. 사용자가 앱을 실행한다.
2. 기존 메모 목록이 최근 수정순으로 표시된다.
3. 사용자가 새 메모를 만들거나 기존 메모를 선택한다.
4. 사용자가 제목 또는 본문을 입력한다.
5. 본문은 마크다운 원문으로 저장되며, 화면에 따라 렌더링 보기 또는 코드 보기로 확인한다.
6. 앱은 입력 내용을 자동 저장한다.
7. 편집 화면 오른쪽 아래에 공백 포함/제외 글자수가 표시된다.
8. 사용자는 필요 시 메모를 검색하거나 상단 고정/위젯 형태로 전환한다.
9. 사용자는 메모를 삭제할 수 있으며, 삭제 전 확인을 받는다.

### 5-3. 주요 화면

| 화면 | 목적 |
|---|---|
| 메인 메모 화면 | 메모 목록 확인 및 메모 작성 |
| 메모 편집 영역 | 제목/본문 입력, 자동 저장, 글자수 확인 |
| 검색 결과 상태 | 제목/본문 기반 검색 결과 표시 |
| 빈 상태 | 첫 사용 또는 검색 결과 없음 안내 |
| 삭제 확인 모달 | 실수 삭제 방지 |
| 위젯형 메모 창 | 데스크톱 위에서 마크다운이 적용된 작은 메모 형태로 접근 |
| 설정 화면 | MVP 이후 저장 경로, 백업, 내보내기 등 로컬 데이터 옵션 관리 |

| FR-012 | 백업/내보내기 | 로컬 데이터를 파일로 내보낼 수 있음 | Low |
| FR-013 | 동기화 대비 데이터 구조 | 향후 동기화를 고려한 ID, 수정시각, 버전 필드를 포함해야 함 | High |
| FR-014 | 설정 내 저장 경로 변경 | MVP 이후 사용자가 설정 화면에서 메모 데이터 저장 폴더를 직접 지정할 수 있어야 함 | Low |
| FR-015 | 마크다운 작성 및 보기 | 본문을 마크다운 형식으로 작성하고 렌더링된 보기로 확인할 수 있어야 함 | High |
| FR-016 | 전체 화면 마크다운 코드 보기 | 전체 메모 관리 화면에서 선택한 메모의 마크다운 원문 코드 보기를 제공해야 함 | Medium |

### 6-2. 운영 요구사항

- 별도 관리자 페이지는 필요 없음
- CS 대응은 MVP 범위에서 제외
- 오류 확인을 위해 로컬 로그 또는 개발자 콘솔 로그를 남길 수 있음
- 저장 실패, 데이터 복구 실패 등 치명 오류는 사용자에게 명확히 표시
- 본인 실사용 중 발견한 문제를 이슈 목록으로 관리

### 6-3. 데이터 요구사항

| 항목 | 설명 |
|---|---|
| note_id | 메모 고유 ID |
| title | 메모 제목 |
| content | 메모 본문 |
| created_at | 생성 시각 |
| updated_at | 마지막 수정 시각 |
| deleted_at | 삭제 시각, soft delete 적용 시 사용 |
| is_pinned | 고정 여부 |
| view_mode | 일반/위젯 등 표시 모드 |
| schema_version | 데이터 구조 버전 |
| char_count_with_spaces | 공백 포함 글자수 |
| char_count_without_spaces | 공백 제외 글자수 |

`content`는 별도 리치 텍스트 구조가 아니라 마크다운 원문 문자열로 저장한다. 렌더링 결과, 보기 모드, 접힘 상태 등 UI 파생 정보는 메모 본문 데이터에 섞지 않는다.

## 7. UX/UI 고려사항

### UX 원칙

- 앱을 켜면 바로 쓸 수 있어야 한다.
- 메모 작성 중 저장 버튼을 의식하지 않아도 된다.
- 글자수 정보는 유용하지만 편집을 방해하지 않아야 한다.
- 데스크톱 작업 흐름 위에 가볍게 얹히는 느낌이어야 한다.
- MVP에서는 기능 발견보다 기본 작성 경험을 우선한다.

### 주요 상태 처리

| 상태 | UX 처리 |
|---|---|
| Loading | 짧은 로딩 표시, 2초 이상 지속되지 않도록 목표 |
| Empty | 새 메모 생성 액션을 바로 제공 |
| Saving | 과도하게 강조하지 않고 작은 상태 텍스트로 표시 |
| Saved | 필요 시 "저장됨"을 보조 텍스트로 표시 |
| Save Failed | 명확한 오류 메시지와 재시도 제공 |
| Search Empty | 검색 결과 없음 표시 |
| Delete Confirm | 삭제 전 확인 모달 제공 |

### 글자수 카운터 UX

- 위치: 편집 화면 오른쪽 아래
- 스타일: 연한 회색 보조 텍스트
- 예시 문구: `공백 포함 128자 · 공백 제외 103자`
- 입력 중 실시간 갱신
- 본문이 비어 있으면 `공백 포함 0자 · 공백 제외 0자`
- 줄바꿈, 탭, 스페이스는 공백 제외 계산에서 제외
- 마크다운 문법 기호를 포함한 원문 기준으로 계산

### 마크다운 UX

- 사용자는 본문을 마크다운 형식으로 작성할 수 있다.
- MVP 기본 문법은 제목, 굵게/기울임, 인라인 코드, 코드 블록, 인용, 순서/비순서 목록, 체크박스, 링크를 우선 지원한다.
- 위젯형 빠른 메모 화면은 마크다운이 적용된 렌더링 보기만 제공한다.
- 위젯에는 마크다운 코드 보기, 편집 툴바, 분할 보기 등 복잡한 작성 보조 UI를 넣지 않는다.
- 전체 메모 관리 화면은 렌더링 보기와 마크다운 코드 보기를 전환할 수 있게 한다.
- 전체 메모 관리 화면의 마크다운 코드 보기는 원문 확인과 수정에 사용한다.
- 인라인 HTML의 `<span style="…">`는 글자색, 배경색, 글자 크기, 굵기, 기울임, 밑줄/취소선 등 허용한 텍스트 스타일만 렌더링하고 편집 후에도 유지한다.
- 이벤트 핸들러, 레이아웃/위치 변경 CSS, HTML 직접 실행, 외부 스크립트, 원격 이미지 자동 로드는 비활성화한다.

## 8. 기술 고려사항

### 구조

- MVP는 로컬 데스크톱 앱으로 구현
- 데이터는 로컬 파일 또는 로컬 DB에 저장
- 추후 동기화를 고려해 메모별 고유 ID와 수정 시각 필수 저장
- 자동 저장은 입력 이벤트마다 즉시 저장하지 않고 debounce 적용
- 데이터 스키마 버전을 저장해 향후 마이그레이션 가능하게 설계
- 마크다운 렌더링은 검증된 파서와 sanitizer를 사용해 원문 저장과 화면 표시를 분리

### 성능 목표

| 항목 | 목표 |
|---|---:|
| 앱 실행 후 입력 가능 시간 | 2초 이내 |
| 메모 입력 반응 | 지연 체감 없음 |
| 자동 저장 지연 | 마지막 입력 후 300~800ms 내 |
| 검색 응답 | 일반 사용량 기준 300ms 이내 |
| 긴 메모 지원 | 최소 10,000자 |

### 보안/백업

- MVP에서는 계정/클라우드 인증 없음
- 로컬 데이터 저장 경로는 명확히 관리
- 가능하면 백업/내보내기 기능을 Phase 2에서 제공
- 동기화 도입 전까지 외부 서버 전송 없음

### 향후: 저장 경로 사용자 설정

- MVP 기본 저장 위치는 OS별 앱 데이터 디렉터리를 사용한다.
- Phase 2에서는 설정 화면에 `저장 위치` 항목을 추가해 사용자가 메모 데이터 저장 폴더를 직접 선택할 수 있게 한다.
- 저장 경로 변경 시 기존 `notes.json` 데이터를 새 위치로 복사 또는 이동할지 사용자에게 확인한다.
- 새 경로는 앱이 읽기/쓰기 권한을 확인한 뒤 적용하며, 권한이 없거나 접근할 수 없는 경로는 저장 실패 상태와 별도 안내를 제공한다.
- 경로 설정값은 메모 데이터 파일과 분리된 앱 설정 파일에 저장한다. 메모 파일 자체에는 Note/NoteStore schema version만 유지한다.
- 경로 변경 후에는 앱 재시작 없이 즉시 저장/로드가 가능한지 검증하되, 실패하면 이전 저장 경로로 되돌릴 수 있어야 한다.

## 9. 실험 및 검증

### 검증 방법

| 검증 항목 | 방법 | 성공 기준 |
|---|---|---|
| 실제 사용성 | 본인이 7일 연속 사용 | 매일 1회 이상 실행/작성 |
| 작성 속도 | 앱 실행 후 새 메모 입력까지 측정 | 2초 이내 |
| 저장 안정성 | 강제 종료/재실행 테스트 | 마지막 저장 상태 복구 |
| 글자수 정확도 | 공백/줄바꿈/탭 포함 테스트 | 기대값과 100% 일치 |
| 삭제 안전성 | 삭제 전 확인 여부 확인 | 실수 삭제 방지 |
| 위젯 사용성 | 작업 중 작은 창으로 사용 | 작업 흐름 방해 없음 |

### AB Test 계획

MVP에서는 정식 AB Test는 진행하지 않는다. 대신 본인 실사용과 1~3명 지인 피드백을 통해 다음 항목을 비교한다.

- 글자수 카운터 위치
- 자동 저장 상태 표시 방식
- 위젯 크기와 기본 위치
- 메모 목록 밀도
- 검색 위치
