# [26.08.25] 로컬 우선 데스크톱 메모 앱 MVP 개발 백로그

## 목표

1~2주 안에 본인이 실제로 사용할 수 있는 로컬 우선 데스크톱 메모 앱 MVP를 만든다.

MVP의 기본 진입 화면은 전체 메모 관리 화면이며, 새 메모를 만들거나 `위젯으로`를 선택하면 위젯형 빠른 메모 화면으로 이동한다.

---

# 0. MVP 범위

## In Scope

- 위젯형 빠른 메모 창
- 제목/본문 입력
- 로컬 저장
- 자동 저장
- 공백 포함/공백 제외 글자수 카운터
- 새 메모 생성
- 전체 메모 관리 화면
- 메모 목록
- 검색
- 삭제 확인
- 상단 고정
- 기본 Empty/Error/Saving/Saved 상태

## Out of Scope

- 계정/로그인
- 클라우드 동기화
- 웹 앱
- 모바일 앱
- 실시간 공동 편집
- 팀/워크스페이스 기능
- 결제/구독
- AI 요약/분류
- 플러그인/마켓플레이스
- 복잡한 권한 관리
- 리치 문서 편집기 수준의 블록 에디터

# 1. 권장 기술 방향

## 추천

- Desktop: Tauri
- UI: React
- Language: TypeScript
- Storage: 로컬 JSON 파일 또는 SQLite
- Repository: 앱별 패키지와 의존성을 분리하는 모노레포
- Window: OS 기본 타이틀바를 제거한 프레임리스 창. Figma 화면 프레임이 곧 실제 앱 창이 되도록 구현한다.

## 현재 저장소 구조

```text
apps/
  desktop/     Tauri + React + TypeScript 데스크톱 앱
idea2planning/ 기획 산출물
```

루트는 향후 웹앱, 모바일 앱, 백엔드 서버를 함께 관리할 수 있도록 모노레포로 유지한다. MVP 구현은 `apps/desktop`에서 먼저 진행한다. 각 앱은 자체 `package.json`, `package-lock.json`, `node_modules`를 갖고, 루트 스크립트는 `npm --prefix apps/desktop ...` 방식으로 앱 명령을 위임한다.

## 판단 기준

- MVP는 빠르고 가벼운 데스크톱 앱 경험이 중요하다.
- 동기화는 MVP 제외지만, 향후 확장을 고려해 데이터 모델은 안정적으로 잡는다.
- 1~2주 목표이므로 복잡한 백엔드나 인증은 만들지 않는다.

# 2. 데이터 모델

```ts
type Note = {
  id: string
  title: string
  content: string
  createdAt: string
  updatedAt: string
  deletedAt: string | null
  isPinned: boolean
  schemaVersion: number
}
```

## 글자수 계산 정책

- 공백 포함: 스페이스, 탭, 줄바꿈 포함
- 공백 제외: 스페이스, 탭, 줄바꿈 제외
- 카운터 문구: `공백 포함 N자 · 제외 N자`
- 본문 기준으로 계산한다.

## EPIC-03. 로컬 저장 및 자동 저장

### TASK-006. 로컬 저장소 설계

- 우선순위: High
- 예상 소요: 0.5~1일
- 설명: 메모 데이터를 저장할 로컬 저장 방식을 결정하고 읽기/쓰기 인터페이스를 만든다.
- 완료 조건:
  - 메모 목록을 로컬에서 읽을 수 있다.
  - 메모를 로컬에 저장할 수 있다.
  - `schemaVersion`이 저장된다.
  - 저장 실패를 호출부에서 감지할 수 있다.

### TASK-007. 자동 저장 구현

- 우선순위: High
- 예상 소요: 1일
- 설명: 제목/본문 변경 후 debounce를 거쳐 자동 저장한다.
- 완료 조건:
  - 입력 후 300~800ms 내 저장이 시도된다.
  - 저장 중에는 `저장 중...` 상태가 표시된다.
  - 저장 성공 시 `저장됨` 상태가 표시된다.
  - 빠른 연속 입력 시 과도한 저장 호출이 발생하지 않는다.

### TASK-008. 앱 재실행 시 데이터 복구

- 우선순위: High
- 예상 소요: 0.5~1일

- 완료 조건:
  - 앱 종료 후 재실행해도 저장된 메모가 남아 있다.
  - 마지막으로 열었던 메모를 표시할 수 있다.
  - 메모가 없으면 Empty 상태를 표시한다.

### TASK-009. 저장 실패 상태 처리

- 우선순위: Medium
- 예상 소요: 0.5일

# 6. 첫 구현 순서

가장 먼저 아래 5개만 끝내면 "돌아가는 MVP의 씨앗"이 생긴다.

2. 위젯형 빠른 메모 UI: 완료, 새 메모 생성 및 전체 메모 화면 전환 연결 완료. 삭제/상단 고정 실제 동작은 후속 작업.
3. 제목/본문 입력: 완료.
4. 글자수 카운터: 완료, 자동 테스트는 TASK-019에서 추가 예정.
5. 로컬 저장: 미시작.

이후 자동 저장, 전체 메모 화면, 검색, 삭제 확인을 붙인다.
