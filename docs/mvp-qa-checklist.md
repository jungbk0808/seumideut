# MVP 확인 체크리스트

## 확인 상태 (2026-10-05)

- 소유자가 아래 Windows 체크리스트를 두 차례 확인했다고 보고했다. 기존 데스크톱 MVP 확인 단계는 완료로 기록한다.
- 아래 절차는 재현 참고용으로 유지한다. 빠른 연속 입력과 저장 실패 강제 재현은 이 체크리스트에 포함되지 않았으므로 백로그에 별도 확인 항목으로 남긴다.
- 7일 실사용은 DB 연동, 독립 웹 앱, 두 환경의 통합 검증을 마친 뒤 시작한다.

## Codex가 확인한 항목 (2026-10-04)

- `npm test`: 본문 글자수(빈 문자열, 한글·영문·숫자, 공백·탭·줄바꿈, 마크다운 기호, 이모지), 제목·본문 검색, 빈 목록 문구 테스트 통과.
- `npm run build`: TypeScript 검사와 프런트엔드 빌드 통과.
- `cargo test --locked`: 저장 파일의 읽기·쓰기, 빠른 연속 수정 후 복구, 저장 실패 감지, 이름 충돌, 제목 변경, 삭제 tombstone, 이전 `notes.json` 마이그레이션 등 15개 테스트 통과.
- 브라우저 개발 화면: 메모 작성 → `저장됨` → 새로고침 후 복구, 제목·본문 검색, 검색 결과 없음, 마크다운 원문/미리보기 전환, 글자수 확인.

브라우저 확인은 개발용 `localStorage`를 사용한다. 아래 Windows 확인은 실제 앱의 `.md` 파일 저장과 창 동작을 검증한다.

## 사용자가 확인한 항목 (Windows, 2회)

실제 메모와 구분되는 제목으로 테스트한다. 삭제 복구 UI는 없으므로 중요한 메모에는 삭제 테스트를 하지 않는다.

1. `npm run desktop:tauri:dev`로 앱을 연다. 작은 위젯이 먼저 열리고 본문에 바로 입력할 수 있는지 확인한다.
2. 제목과 본문에 한글·영문·숫자·공백·탭·줄바꿈을 입력한다. 글자수가 입력 중 바뀌고 잠시 뒤 `저장됨`이 표시되는지 확인한다.
3. 앱을 닫고 다시 열어 제목·본문이 복구되는지 확인한다. 전체 메모 화면에서 제목과 본문 검색을 각각 시도한다.
4. 위젯에서 `+`를 눌러 새 위젯이 옆에 열리는지 확인한다. `전체 메모 열기`를 반복해서 눌렀을 때 전체 메모 창이 중복 생성되지 않는지 확인한다. 전체 메모 창을 최소화한 뒤 위젯의 `전체 메모 열기`를 누르면 기존 창이 복원되고 해당 메모가 선택되어야 한다.
5. 핀을 켠 위젯 위로 다른 Windows 창을 가져와 위젯이 위에 유지되는지 확인한다. 핀을 끄면 일반 창처럼 동작해야 한다. 위젯을 선택하면 은은한 그림자가 나타나고, 다른 창을 선택하면 그림자가 사라져야 한다. 커서만 위젯 안팎으로 움직일 때에는 그림자가 바뀌지 않아야 한다. 고정 여부와 관계없이 같은 기준을 사용하며, 그림자가 바뀌어도 메모 영역의 크기나 위치는 움직이지 않아야 한다.
6. 위젯을 기본 크기로 열고 모서리를 안쪽으로 드래그해 더 줄어들지 않는지 확인한다. 크게 늘렸다가 다시 줄여도 기본 크기에서 멈춰야 한다. 이 크기에서 10,000자 이상의 메모를 스크롤하며 본문과 하단 저장 상태·글자수가 잘리지 않는지 확인한다.
7. 테스트 메모에서 삭제를 누른다. 확인창의 `취소`로 메모가 유지되는지 확인한 뒤, 다시 열어 `삭제`를 선택하고 목록에서 사라지는지 확인한다.
8. 전체 화면 코드 보기에 `<span style="color: red">가</span>`를 입력한다. 미리보기에서 Enter 한 번 후 입력한 글자는 빨간색을 유지하고, 곧바로 Enter를 한 번 더 누른 뒤 입력한 글자는 기본 색인지 확인한다. 코드 보기의 줄바꿈 수와 `# 제목`, `**강조**`의 글자수도 확인한다.

문제가 보이면 날짜, 재현 순서, 기대 결과, 실제 결과를 아래 기록에 남긴다. 화면이 잘리거나 창이 잘못 열리면 화면 크기와 Windows 배율도 적는다.

## Google 로그인 확인 (2026-10-11, 핵심 흐름 소유자 확인 완료)

자동 검사: 프런트엔드 36개 테스트·빌드, Rust 20개 테스트 통과. Windows 암호화 저장·교체·callback 파싱 검증. 브라우저 설정 화면에서 로그인 버튼 표시 확인. 원격 Google provider 활성화·비로그인 메모 조회 차단 확인.

소유자가 실제 로그인, 앱 재실행 후 로그인 유지, 로그아웃 후 재실행에도 로그아웃 유지, 재로그인과 기존 메모 보존을 모두 정상 확인했다고 보고했다. 아래 1~4번 핵심 흐름은 완료로 기록한다. 5~6번 취소·시간 초과의 실제 브라우저 확인은 아직 완료 보고가 없으며 자동 테스트로 확인한 상태다.

1. 기존 개발 서버를 닫고 `npm run desktop:tauri:dev`로 Windows 앱을 실행한다. 위젯의 `전체 메모 열기` → 설정으로 이동한다.
2. `Google로 로그인`을 누르고 기본 브라우저에서 본인 계정을 선택한다. 복귀 탭 안내 후 앱 설정에 본인 이메일과 `로그아웃`이 표시되는지 확인한다.
3. 앱을 완전히 종료하고 재실행한다. 전체 메모 → 설정에서 같은 이메일이 복구되는지 확인한다.
4. 로그아웃 후 `로그인하지 않음`으로 바뀌는지, 재실행해도 로그아웃 상태인지, 기존 메모가 그대로인지 확인한다.
5. 다시 로그인 버튼을 누른 뒤 앱에서 `취소`한다. 이전 브라우저 응답이 뒤늦게 도착해도 로그인되지 않아야 한다. 다시 버튼을 눌러 새 로그인은 완료할 수 있어야 한다.
6. Google에서 동의를 취소하거나 대기 시간이 5분을 넘으면 앱에 재시도 안내가 표시되는지 확인한다.

현재 로그인은 계정 인증까지만 연결되어 있다. 로컬 메모가 DB에 자동 업로드되거나 다른 계정의 메모로 전환되지는 않는다. 실제 두 계정의 원격 RLS와 PC·웹 동기화는 해당 구현 후 별도로 검증한다.
