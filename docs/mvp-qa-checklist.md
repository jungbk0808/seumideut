# MVP 확인 체크리스트

## 확인 상태 (2026-10-05)

- 소유자가 아래 Windows 체크리스트를 두 차례 확인했다고 보고했다. 기존 데스크톱 MVP 확인 단계는 완료로 기록한다.
- 아래 절차는 재현 참고용으로 유지한다. 빠른 연속 입력과 저장 실패 강제 재현은 이 체크리스트에 포함되지 않았으므로 백로그에 별도 확인 항목으로 남긴다.
- 7일 실사용은 DB 연동, 독립 웹 앱, 두 환경의 통합 검증을 마친 뒤 시작한다.

## Codex가 확인한 항목 (2026-10-04)

- `npm test`: 본문 글자수(빈 문자열, 한글·영문·숫자, 공백·탭·줄바꿈, 마크다운 기호, 이모지), 제목·본문 검색, 빈 목록 문구 테스트 통과.
- `npm run build`: TypeScript 검사와 프런트엔드 빌드 통과.
- `cargo test --locked`: 저장 파일의 읽기·쓰기, 빠른 연속 수정 후 복구, 저장 실패 감지, 이름 충돌, 제목 변경, 삭제 tombstone, 이전 `notes.json` 마이그레이션 등 15개 테스트 통과.
- 브라우저 개발 화면: 메모 작성 → `저장됨` → 새로고침 후 복구, 제목·본문 검색, 검색 결과 없음, 마크다운 원문/미리보기 전환, 글자수 확인.

브라우저 확인은 개발용 `localStorage`를 사용한다. 아래 Windows 확인은 실제 앱의 `.md` 파일 저장과 창 동작을 검증한다.

## 사용자가 확인한 항목 (Windows, 2회)

실제 메모와 구분되는 제목으로 테스트한다. 삭제 복구 UI는 없으므로 중요한 메모에는 삭제 테스트를 하지 않는다.

1. `npm run desktop:tauri:dev`로 앱을 연다. 작은 위젯이 먼저 열리고 본문에 바로 입력할 수 있는지 확인한다.
2. 제목과 본문에 한글·영문·숫자·공백·탭·줄바꿈을 입력한다. 글자수가 입력 중 바뀌고 잠시 뒤 `저장됨`이 표시되는지 확인한다.
3. 앱을 닫고 다시 열어 제목·본문이 복구되는지 확인한다. 전체 메모 화면에서 제목과 본문 검색을 각각 시도한다.
4. 위젯에서 `+`를 눌러 새 위젯이 옆에 열리는지 확인한다. `전체 메모 열기`를 반복해서 눌렀을 때 전체 메모 창이 중복 생성되지 않는지 확인한다.
5. 핀을 켠 위젯 위로 다른 Windows 창을 가져와 위젯이 위에 유지되는지 확인한다. 핀을 끄면 일반 창처럼 동작해야 한다.
6. 위젯을 `350×420` 정도로 줄이고 10,000자 이상의 메모를 스크롤한다. 본문 스크롤과 하단 저장 상태·글자수가 잘리지 않는지 확인한다.
7. 테스트 메모에서 삭제를 누른다. 확인창의 `취소`로 메모가 유지되는지 확인한 뒤, 다시 열어 `삭제`를 선택하고 목록에서 사라지는지 확인한다.
8. 전체 화면 코드 보기에 `<span style="color: red">가</span>`를 입력한다. 미리보기에서 Enter 한 번 후 입력한 글자는 빨간색을 유지하고, 곧바로 Enter를 한 번 더 누른 뒤 입력한 글자는 기본 색인지 확인한다. 코드 보기의 줄바꿈 수와 `# 제목`, `**강조**`의 글자수도 확인한다.

문제가 보이면 날짜, 재현 순서, 기대 결과, 실제 결과를 아래 기록에 남긴다. 화면이 잘리거나 창이 잘못 열리면 화면 크기와 Windows 배율도 적는다.
